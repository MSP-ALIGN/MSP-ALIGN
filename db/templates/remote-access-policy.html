Remote Access Policy

{{client_name}} · Effective {{today}} · Maintained with {{company_name}}

1. Purpose

This policy defines how workforce members, vendors and {{company_name}} may connect to {{client_name}} systems from outside the office, so that remote work and remote support do not create an easy path for attackers. Exposed remote desktop services and unmanaged remote access tools are among the most common entry points for ransomware.

2. Scope

This policy covers all remote connections to {{client_name}} networks, servers, workstations and applications, including VPN and zero trust network access (ZTNA), remote desktop and remote desktop gateways, remote control and remote support tools, access to on-premises line-of-business applications from outside the office, and administrative access to cloud services, firewalls and other infrastructure. It applies to employees, contractors, vendors and {{company_name}} staff, whether they use company-owned or personal devices.

Ordinary use of cloud services such as Microsoft 365 from a managed or approved device is governed by the Access Control, Password & MFA and Mobile Device & BYOD policies.

3. Roles and responsibilities

  • Security lead ([name, title]): approves who may work remotely and which vendors may connect, and approves exceptions.
  • Managers: request remote access for staff who need it and notify {{company_name}} when it is no longer required.
  • {{company_name}}: selects, configures and monitors approved remote access technologies; controls the remote support toolset; reviews remote access logs and alerts.
  • Remote users: follow this policy, protect their devices and home networks, and report problems or suspected compromise immediately.

4. Approved remote access methods

Only the following methods may be used. All other remote access tools and methods are prohibited.

  • Cloud applications with MFA: Microsoft 365 / Google Workspace and approved SaaS applications, protected by conditional access and MFA.
  • VPN or ZTNA: [product name, e.g. firewall SSL VPN, WireGuard, or a ZTNA service] for access to on-premises resources, requiring MFA on every connection. ZTNA, which grants access to specific applications rather than the whole network, is preferred for new deployments.
  • Remote desktop gateway or published applications: [product name], only behind VPN/ZTNA or a gateway that enforces MFA.
  • {{company_name}}'s remote support tools: the RMM and remote support platforms managed by {{company_name}} ([tool names]), used by authorized technicians only.

5. Security requirements for remote access

  • MFA on every remote connection. No remote access method that grants access to internal networks or systems may rely on a password alone.
  • No exposed RDP or management interfaces. Remote Desktop Protocol (TCP 3389), SSH, SMB, database ports and firewall, NAS, camera or printer management pages must never be directly reachable from the internet. {{company_name}} verifies this with external scans at least quarterly.
  • Encryption: remote connections use TLS 1.2 or higher, or IPsec/WireGuard using approved algorithms per the Encryption Policy.
  • Device requirements: remote access to internal networks is allowed only from company-managed devices, or from personal devices through published applications/virtual desktops that do not allow data to be saved locally. Devices must have a supported operating system, current patches, active endpoint protection and full-disk encryption.
  • Split tunneling: [allowed for internet traffic / disabled] as configured by {{company_name}}. Where CUI or cardholder data is accessed, split tunneling is disabled unless the device is otherwise protected, consistent with CMMC SC.L2-3.13.7.
  • Geographic and risk restrictions: sign-ins from countries where {{client_name}} does not operate are blocked by conditional access unless a travel exception is requested in advance. High-risk sign-ins are blocked or require re-authentication.
  • Remote access firewall rules limit VPN users to the specific servers and ports needed for their role.

6. Session timeouts

  • VPN and ZTNA sessions disconnect after 30 minutes of inactivity and require re-authentication at least every 12 hours.
  • Remote desktop sessions disconnect after 15 minutes idle and log off disconnected sessions after [2] hours.
  • Administrative sessions to firewalls, servers and cloud consoles time out after 15 minutes idle.
  • Remote workstations lock after 15 minutes of inactivity.

7. Remote support tools

  • Remote control and support tools are controlled by {{company_name}}. Only the tools listed in section 4 are permitted. Consumer or unapproved tools (for example personal TeamViewer, AnyDesk, Chrome Remote Desktop, ScreenConnect instances not owned by {{company_name}}) are blocked by endpoint controls where possible and removed if found.
  • Technician access to remote support tools requires individual named accounts and phishing-resistant MFA; technician sessions are logged with who connected, to which device, and when.
  • Attended sessions on user workstations notify the user that a session is active.
  • Users must never install a remote access tool or allow a remote session at the request of an unsolicited caller, pop-up or email. Legitimate {{company_name}} technicians will identify themselves and can be verified by calling {{company_phone}}.
  • Vendors who support line-of-business systems connect through a {{company_name}}-controlled method, receive access only when a session is scheduled or requested, and have access disabled when the session ends. Always-on vendor access requires security lead approval and is reviewed quarterly.

8. Home networks and public Wi-Fi

  • Home Wi-Fi used for work must use WPA2-Personal (AES) or WPA3 with a strong passphrase, and the router's default admin password must be changed. Router firmware should be kept up to date.
  • Work devices should not share a network segment with devices of unknown security where a guest or separate network is available.
  • On public Wi-Fi (hotels, coffee shops, airports), users must connect to the VPN/ZTNA before accessing company resources, or use a mobile hotspot. Never accept certificate warnings or install software prompted by a captive portal.
  • Screens must not be visible to others in public places when working with Confidential or Restricted information; use a privacy screen where practical.
  • Printing Confidential or Restricted information at home or in public locations is not allowed unless approved; any printed material must be secured and shredded.

9. Monitoring and review

  • Remote access connections, failures and administrative actions are logged and forwarded to centralized monitoring per the Logging & Monitoring Policy.
  • {{company_name}} reviews the list of users with VPN/ZTNA access and vendor remote access quarterly as part of the access review.
  • Remote access for departing users is disabled as part of offboarding within 24 hours.

10. Exceptions

Any exception, such as a legacy application requiring direct access, must be documented with compensating controls (for example IP allow-listing and a gateway with MFA), approved by the security lead, and reviewed at least every 6 months.

11. Enforcement

Installing unapproved remote access tools, sharing VPN credentials, or bypassing remote access controls may result in loss of remote access privileges and disciplinary action up to and including termination.
